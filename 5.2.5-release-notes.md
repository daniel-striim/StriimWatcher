## ✨ Full Release Notes: Monitoring Tables & System Enhancements

---

### 📊 New Monitoring Tables

This release introduces several new tables to enhance information tracking and monitoring capabilities:

* **Source & Target Information Tracking**
    These tables track a range of information related to **Sources** and **Targets**. They also include an optional `'Detail'` field which contains the JSON output from the command `"mon source/target;"`.
    * `striim_mon_source_information`
    * `striim_mon_target_information`

* **Checkpoint History Table**
    Gathers the output from the command **`"show <appName> checkpoint history;"`** for all applications.
    * `striim_mon_checkpoint_history`

* **Oracle Open Transaction Table**
    Monitors and reports any **Oracle Open Transactions (Trx)**.
    * `striim_mon_oracle_open_trx`
    > *Note: Not yet tested.*

* **File Lineage Table**
    Monitors **File Lineage**.
    * `striim_mon_file_lineage`
    > *Note: Not yet tested.*

* **Server Configuration and Properties Table**
    Returns **server configuration** details, including `startUp.properties`. It only reports changes that are detected in the configuration.
    * `striim_mon_system_configuration`

### ⚙️ System Enhancements

#### **Auto Vault Checkin**
If this option is selected, it triggers an **auto-renewal of connectivity/auth tokens** for vaults, which is useful during periods of low activity. This is achieved by running the following commands in sequence, and it **does not generate an output**:
1. `list vaults;`
2. `read all from <vaultName>;`

#### **Updated Information Gathering (Log Watcher)**
New flags have been added to the **Log Watcher** to gather additional logs into the LogWatcher Table:
* New flag to gather `striim.server.clidebug.log`.
* New flag to gather `striim.command.log`.

#### **Autoheal Monitoring Apps**
This feature monitors the status of essential monitoring applications on each node (`status <node>`). It can attempt to **RESUME** them if they are found to be stopped. This helps protect the data gathering process for **StriimWatcher**.
* **Monitored Applications:**
    * `"Global.MonitoringProcessApp"`
    * `"Global.MonitoringSourceApp"`
    * `"System$Alerts.AlertingApp"`
    * `"System$Notification.NotificationSourceApp"`
    * `"System$PIIGlobal.SystemAIGlobalApp"`

#### **Metadata Repository (MDR) Calls**
* **Updated and reorganized calls to the MDR**, which is expected to **reduce/minimize** the number of calls needed per API command.
